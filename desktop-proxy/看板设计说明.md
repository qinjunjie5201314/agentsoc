# AgentSoc 桌面代理 · 本地看板设计说明

> 目标：安装 proxy 后，能直接在终端上看到「代理联通状态 / 电脑主机名 / 是否命中规则」，
> 无需登录任何后台、不依赖服务端改造。

## 一、要解决的三个问题

| 诉求 | 数据来源 | 实现方式 |
|------|----------|----------|
| 当前代理联通状态 | 代理周期探活上游网关 /v1/info | 后台 goroutine 每 5s 发一次 HTTP GET，记录可达性 + 延迟 |
| 电脑的主机名称 | 本机 OS | os.Hostname()，随状态上报 |
| 是否命中规则 | 网关的拦截响应体 | 代理转发后解析 HTTP 400 响应里的 agentsentry 结构（rule_hits / score / risk / policy） |

## 二、架构（零服务端改造）

- 看板是代理进程内部的一个 HTTP 服务，绑定 127.0.0.1:8890，不对外开放。
- 所有状态数据只驻留本机内存，不落盘、不上报第三方。
- 显式模式 / 透明 MITM 模式共用同一份 handle 转发逻辑，因此两种模式都能采集。

## 三、数据流

1. 请求进来：handle() 转发到上游网关。
2. 响应回来：
   - 状态码 >= 400（拦截/错误）：读全量 body，若含 agentsentry 则解析出 rule_hits / classifier_max_score / risk_level / policy.version，记为一条「拦截」事件；否则记为「错误」。
   - 状态码 2xx：记为「通过」（未命中规则）。
3. 每 5s 探活一次上游 /v1/info，更新「联通状态 / 延迟」。
4. 浏览器每 2s 拉一次 GET /api，渲染卡片 + 流水表。

## 四、部署（可落地步骤）

```bash
cd desktop-proxy
go build -o agentsoc-proxy.exe .        # 编译（dashboard.html 由安装包随附，运行时从 exe 同目录读取）
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" installer.iss   # 重新打包
```

- 安装包双击安装后会 -setup 自动注册服务并写入 dashboard: 127.0.0.1:8890 到 config.json。
- 终端用户浏览器打开 http://127.0.0.1:8890 即可看到看板。

## 五、关闭看板

在 config.json 设 "dashboard": ""，或启动时加 -dashboard ""，看板服务不启动（代理转发不受影响）。

## 六、安全边界

- 仅监听 127.0.0.1，同机浏览器可访问，局域网其他机器不可达。
- 历史记录仅存内存（环形 200 条），重启即清空，不写文件、不联网上报。
- 不含任何凭据；探活只发匿名 GET。

## 七、可扩展：集团级「多终端在线总览」（后续）

当前看板是「每终端自看」。若要安全/合规团队在一个后台看全部终端在线情况，需加一层：

1. 网关侧新增 POST /v1/heartbeat 接收端，代理每分钟上报 {hostname, mode, upstream, conn_ok, blocked, passed}。
2. 网关用 SQLite/现有审计库存最近心跳，提供 GET /v1/terminals 列表（按 last_seen 排序，>10min 标记离线）。
3. 另做一个服务端「集团总览页」展示所有终端矩阵。

此扩展需要服务端改造 + 数据库，本期看板先交付单机自看版本，后续按需开启。
