## 一、我们为什么做这个产品（设计背景）

### 一个正在发生的时代断层

2024 年以来，AI Agent（智能体）从"回答问题"进化到"自主行动"——它能读文件、调 API、发邮件、跑命令、操作数据库。企业开始把真实的生产环节交给 Agent。

但这里有一个**被严重低估的安全断层**：

> 传统安全防护的对象是"人"，而 AI Agent 是一个"会自主执行指令的程序"。
> 我们熟悉的防火墙、WAF、DLP，全是给人设计的——**它们拦不住"一个被诱导的 AI 去执行危险操作"。**

### 三类真实的痛

1. **Prompt 注入攻击**：攻击者把恶意指令藏在正常对话里，诱导 Agent 泄露数据、执行危险命令。不需要任何漏洞，只需要"会说话"。
2. **工具滥用**：Agent 被授予了调用工具（bash、数据库、HTTP）的能力，但缺乏执行前的安全校验。一次被诱导的 `rm -rf` 就是灾难。
3. **责任不可追溯**：安全/合规团队要问"这个 AI 做了什么、谁让它做的、被谁拦了"，却无从查证——因为没人给 Agent 建审计账本。

### 我们的判断

AI 安全不是"再上一个 LLM"，而是一个**运行时防护层**——像给 AI 装一套"安全带 + 行车记录仪"。

这就是 AgentSoc 的起点。

## 二、我们解决了什么问题

一句话：**让企业敢放心地把 AI Agent 放进生产环境。**

具体拆成四个可验证的承诺：

| 问题 | AgentSoc 的解法 |
|---|---|
| AI 分不清正常请求和恶意指令 | L1-L4 纵深防御，在模型执行前拦截攻击 |
| 攻击者用编码/零宽字符绕过检测 | L1 归一化层还原真实语义，编码走私照样识破 |
| Agent 越权调用危险工具 | L4 工具兜底，执行前校验，被拦绝不执行 |
| 出了事查不到、说不清 | 全量审计 + 会话回放 + 策略版本溯源 + 变更审批台账 |

**核心价值主张**：不只是"拦截攻击"，而是给企业提供**可审计、可追溯、可出报表**的合规能力——让安全团队"责任可转移"。

## 三、技术架构

### 3.1 架构总览

```
                 ┌─────────────────────────────────────┐
   AI Agent /    │          AgentSoc Runtime            │
   客户端请求     │                                     │
      │          │  L1 归一化  ──► L2 来源隔离 ──► L3 检测  │
      ▼          │       │              │              │
  ┌────────┐     │       └──────────────┘              │
  │  Proxy │────►│                                     │
  │(OpenAI │     │  L4 工具兜底 ──► 放行 / 拦截          │
  │兼容)   │     │                                     │
  └────────┘     │  审计落库 ◄── 策略中心 ◄── 报表/审批  │
                 └─────────────────────────────────────┘
```

### 3.2 四层纵深防御（核心）

| 层 | 职责 | 实现 |
|---|---|---|
| **L1 归一化** | URL/Unicode/HTML/Base64/零宽字符解码，还原攻击真实语义 | `app/detection/normalize.py` |
| **L2 来源隔离** | 区分 system/user/tool 三类来源，防止工具结果注入 | `app/detection/isolate.py` |
| **L3 检测分级** | 规则引擎 + 判别模型 + 决策融合（任一命中即升级） | `app/detection/{rules,classifier,fuse}.py` |
| **L4 输出兜底** | 工具调用前 JSON 校验 + 白/黑名单 + 高危语义拦截 | `app/detection/egress.py` + `tool_hook.py` |

### 3.3 关键工程特性

- **零侵入接入**：OpenAI 兼容 Proxy，改一个 `base_url` 即可接入，无需改业务代码
- **策略热更新**：YAML 策略改完毫秒级生效，无需重启
- **内容寻址版本**：每条拦截带策略版本号，可回答"哪版策略拦的"
- **异步审计**：落库不阻塞主链路，审计失败不影响防护
- **容器化部署**：Docker Compose 一键启动，非 root 运行，管理端点鉴权

### 3.4 技术栈

Python 3.11 / FastAPI / SQLAlchemy / SQLite(→PG) / 规则引擎自研 DSL / 判别模型可选本地 HF 或远程 API / Docker

## 四、产品功能

### 4.1 已交付（M1 + 阶段 1 + 阶段 2）

**安全防护**
- Prompt 注入 / 角色劫持 / 系统提示泄露 / 数据外泄 / 高危 shell / 编码走私 拦截
- 工具调用白黑名单 + 参数校验 + 高危语义检测

**策略管理**
- 策略配置中心（YAML + 热更新 + fail-safe 回滚）
- 自然语言转策略（写"禁止 bash 删 /etc"自动生成策略）
- 策略变更审批台账（提案 → 审批 → 生效，全程留痕）

**审计合规**
- 全量审计日志（会话 / 风险事件 / 审计日志三表）
- 会话回放（完整 timeline）
- 审计报表（汇总 / 规则 TOP / 来源分布 / 日趋势）+ CSV/JSON 导出
- 误报率统计

**可观测**
- Prometheus 指标 / 健康探针 / CLI 实时风险事件流

**可视化**
- 6 个互链 Demo 页（dashboard / 攻击演示 / 工具拦截 / 策略中心 / NL转策略 / 审计回放）

### 4.2 验证数据

- 30+ 攻击样例全链路回归测试，7 类攻击全拦截、正常请求零误伤
- 攻击演练 9/9 拦截通过
- 550 项自动化测试通过

## 五、未来可落地的商业化方案

### 5.1 商业化路径（分三阶段）

| 阶段 | 形态 | 目标 | 收入模式 |
|---|---|---|---|
| **近期（0-6月）** | 内部工具 → 开源 | 建立信任与社区 | 免费 + 技术影响力 |
| **中期（6-18月）** | 企业私有化部署 | 安全/合规团队买单 | License 订阅 + 服务费 |
| **远期（18月+）** | 平台化 SaaS / 云服务 | 规模化 | 按调用量/按 Agent 数订阅 |

### 5.2 三个可落地的商业场景

**场景 1：企业私有化安全套件（最直接）**
- 卖给"已经在用 AI Agent、但有合规压力"的企业
- 定价：按部署节点/Agent 数量年费订阅
- 价值点：等保 2.0 / SOC2 / 数据安全法的审计合规能力

**场景 2：Agent 平台的安全中间件**
- 集成到 AI Agent 开发平台（如 Coze、Dify、企业内部 Agent 平台），作为"安全网关"插件
- 定价：按平台调用量分成或按 seat 收费

**场景 3：安全合规审计服务**
- 不卖软件，卖"AI 安全审计报告"服务——帮企业评估其 Agent 的安全风险，出合规报告
- 定价：按项目咨询费

### 5.3 差异化壁垒

1. **运行时防护**（不是静态扫描，是 Agent 执行前的实时拦截）
2. **合规闭环**（不只是拦截，而是"拦截 + 审计 + 报表 + 审批"四位一体）
3. **零侵入接入**（改 base_url 即可，降低企业决策成本）
4. **可私有化**（数据不出企业，满足金融/政务等敏感行业）

### 5.4 需要补的关键能力（商业化前）

- 真实判别模型（降低误报率到生产可用水平）
- 多租户 / 账号体系
- 审计日志脱敏 + 哈希链防篡改
- 企业 SSO / OIDC 集成
- 性能压测与 SLA 保障
