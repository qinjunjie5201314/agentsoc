# 安全自证 · 威胁建模与加固说明

> 阶段 1 工程化产物。安全产品自身的威胁面分析 + 已做加固项 + 待办清单。

---

## 一、威胁面分析

AgentSoc 是一个「横在 AI Agent 和模型之间的代理」，它的攻击面如下：

| # | 威胁 | 风险 | 现状 |
|---|---|---|---|
| T1 | 管理端点未鉴权，任意人可改策略/读审计日志 | 高 | ✅ 已加 API Key 鉴权（`app/security.py`） |
| T2 | 审计日志含敏感 prompt，泄露后造成二次伤害 | 高 | ⚠️ 依赖部署环境隔离，M2 加脱敏 |
| T3 | 自身依赖有已知漏洞（CVE） | 中 | ⚠️ 需在 CI 加依赖扫描 |
| T4 | 容器以 root 运行，被攻破后权限过大 | 中 | ✅ 已改非 root 用户（`agentsoc` uid 1000） |
| T5 | 时序侧信道攻击（对比 API Key 耗时） | 低 | ✅ 用 `secrets.compare_digest` 常量时间比较 |
| T6 | 代理被用作 SSRF（转发恶意 URL） | 低 | ⚠️ M2 加出站 URL 白名单 |
| T7 | DoS：超长输入拖垮检测/模型推理 | 中 | ⚠️ M2 加输入长度上限 + 限流 |

---

## 二、已完成的加固（阶段 1）

1. **管理端点鉴权**：设 `API_KEY` 后，`/v1/policy/*`、`/v1/audit/*`、`/v1/policy/nl/*` 需带 `X-API-Key` 头。
2. **常量时间比较**：`secrets.compare_digest`，防时序侧信道。
3. **容器非 root**：Dockerfile `USER agentsoc`（uid 1000）。
4. **优雅降级**：判别模型加载失败 → 自动降级纯规则引擎，不阻断服务。
5. **审计不反噬主链路**：落库失败只记 warning，不影响拦截/放行决策。

## 四、验证方法

```bash
# 1. 设 API_KEY 启动
export API_KEY=test-secret
uvicorn app.main:app --port 8000

# 2. 无 key 访问管理端点 → 401
curl -i http://127.0.0.1:8000/v1/audit/events

# 3. 带 key → 200
curl -H "X-API-Key: test-secret" http://127.0.0.1:8000/v1/audit/events

# 4. 业务端点不受影响（无需 key）
curl http://127.0.0.1:8000/health
```
