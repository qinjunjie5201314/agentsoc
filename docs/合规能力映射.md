# AgentSoc 合规能力映射文档

> 面向企业安全/合规团队：说明 AgentSoc 如何对应主流合规标准的要求。
> 用途：内部安全评审、合规自查、审计答辩的"弹药"。
> 注：本文档是**能力映射**，不是合规认证；具体是否符合某标准，仍需结合贵司完整安全体系评估。

---

## 一、AgentSoc 提供的合规能力清单

| 能力 | 对应功能 | 说明 |
|---|---|---|
| **访问控制** | 管理端点 API Key 鉴权 | 策略/审计端点需 `X-API-Key`，`secrets.compare_digest` 防时序攻击 |
| **审计日志** | 三表落库（sessions/risk_events/audit_logs） | 每次检测/工具调用全量留痕 |
| **审计追溯** | 策略版本号（revision + sha256） | 每条拦截可回答"哪版策略拦的" |
| **变更管理** | 策略变更审批台账 | 提案 → 审批 → 生效/拒绝，全程留痕 |
| **报表** | 周期报表 + 导出（CSV/JSON） | 拦截量、规则 TOP、来源分布、日趋势 |
| **会话回放** | 完整 timeline | 还原"谁、何时、做了什么、被谁拦" |
| **数据留存** | 审计保留策略（`audit_retention_days`） | 可配置留存周期 |

## 二、等保 2.0 映射（GB/T 22239-2019）

> 等保 2.0 三级通用要求里，与本产品直接相关的控制点：

| 等保控制点 | 要求概述 | AgentSoc 对应 |
|---|---|---|
| 安全审计（8.1.4.3） | 启用审计功能，记录安全事件 | ✅ 全量审计日志落库 |
| 审计记录保护 | 审计记录防篡改、可追溯 | ✅ 策略版本 + 会话回放（哈希链 M2 待补） |
| 访问控制 | 最小权限、身份鉴别 | ✅ 管理端点 API Key 鉴权 |
| 入侵防范 | 检测/阻断攻击行为 | ✅ L1-L4 纵深防御（prompt 注入/工具滥用） |
| 数据完整性 | 关键数据防篡改 | ⚠️ 策略内容 sha256 版本化（审计日志哈希链待补） |
| 安全事件处置 | 记录、分析、上报 | ✅ 风险事件分级（low/medium/high）+ 命中规则 |

**待补（对应等保更严格项）**：
- 审计日志哈希链（防篡改自证）
- 管理端点接企业身份认证（OIDC/LDAP，替代 API Key）
- 审计日志脱敏（敏感信息掩码）

## 三、SOC 2 映射（AICPA Trust Services Criteria）

> SOC 2 的五个信任服务原则中，与本产品直接相关的：

| TSC 原则 | 要求 | AgentSoc 对应 |
|---|---|---|
| **Security** | 访问控制、系统防护 | ✅ API Key 鉴权 + L1-L4 防护 |
| **Availability** | 系统可用性 | ✅ /health + /healthz 探针 + Docker 容器化 |
| **Processing Integrity** | 处理准确、完整 | ✅ 检测结果带策略版本，可验证 |
| **Confidentiality** | 敏感数据保护 | ⚠️ 审计日志含敏感 prompt，需脱敏（待补） |
| **Privacy** | 个人信息保护 | ⚠️ 依赖部署方配置（待补脱敏 + 留存策略） |

**关键控制（CC 系列）映射**：
- CC6.1（逻辑访问控制）→ 管理端点鉴权
- CC7.2（安全事件监控）→ 审计日志 + 报表 + 告警
- CC8.1（变更管理）→ 策略变更审批台账

## 四、数据安全法 / 个人信息保护法映射

| 要求 | AgentSoc 对应 |
|---|---|
| 数据处理留痕、可审计 | ✅ 全量审计日志 + 会话回放 |
| 数据最小化 | ⚠️ 审计存 `input_snippet` 截断 500 字符（已做部分） |
| 数据留存期限管理 | ✅ `audit_retention_days` 可配（默认 90 天） |
| 数据安全事件记录与上报 | ✅ 风险事件分级 + 命中规则 + 报表导出 |

## 五、给安全/合规团队的使用建议

1. **接入即合规基础**：只要 Agent 走 AgentSoc proxy，就自动获得"访问控制 + 审计 + 变更管理"三重能力。
2. **定期导出报表**：`GET /v1/audit/report/export?fmt=csv` 做月度审计归档。
3. **策略变更走审批**：`POST /v1/policy/change` 提交提案，而非直接改 YAML，保证变更可追溯。
4. **配置留存策略**：根据内部要求设 `AUDIT_RETENTION_DAYS`。
